# Отчёт о тестировании

Дата: 28.10.2026. Godot 4.4.1-stable, Linux x86_64.
Автотесты: `godot --headless --path . -s tests/run_tests.gd`.

**Итог последнего прогона (версия 1.1.0): 7 наборов, 55 тестов, ≈16 770 проверок, 0 ошибок.** (Число проверок в `test_scenes` немного меняется: зависит от длины партии бота.)

> **Важно.** Проверка на реальном Android-устройстве или эмуляторе **не
> проводилась**: в среде разработки нет ни устройства, ни аппаратной
> виртуализации для эмулятора. APK собран и проверен статически, игра
> запускалась на Linux тем же движком и тем же рендерером (GL Compatibility),
> что используется на Android.

записывает провал и продолжает; лёд под плодом был почти не виден — перенесён

## Этап 3. Логика Match-3 (`test_board_model` 21 тест / 9 853 проверки, `test_level_goals` 5 / 33)

| Требование | Как проверено |
|---|---|
| Корректность совпадений | ряд из 3: очищены ровно 3 нужные клетки, поле дозаполнено |
| Возврат недопустимых ходов | обмен без совпадения, через клетку, по диагонали, за край — отклонены, поле не изменилось |
| Каскады | 60 случайных партий × 30 ходов: после каждого хода поле полное, нет готовых совпадений, есть допустимый ход |
| Специальные элементы | 4 в ряд → ракета (горизонтальная/вертикальная), Т/Г → корзина, 5 → радуга; ракета чистит ряд, корзина 5×5, радуга — весь цвет, цепная реакция ракета→корзина |
| Комбинации усилителей | ракета+ракета = крест (15), корзина+корзина = 7×7 (49), ракета+корзина = 3+3 линии (39), радуга+радуга = всё поле (64), радуга+ракета превращает плоды в ракеты |
| Перемешивание | заведомо «тупиковое» поле: после перемешивания есть ход, нет готовых совпадений, плоды не потеряны |
| Нет бесконечных циклов | число фаз за ход ограничено (не более 42), проверено на всех случайных партиях |
| Стартовое поле | 250 стартов (10 уровней × 25 зёрен): нет готовых совпадений, есть ход, все клетки заполнены |
| Сорняки | очищаются совпадением рядом и ракетой; «толстые» — за 2 удара; плоды падают за сорняками |
| Помощники в логике | Петя — ровно 5 обычных плодов, Белка — 1 клетка, Ёжик — 3×3 (в углу 2×2) |
| Звёзды | 6 комбинаций запаса ходов/условий, повторный расчёт даёт тот же результат |

Найдено и исправлено: ошибка в расчёте ячеек в двух тестах (тестовые поля
изначально содержали совпадение; ожидаемое число клеток для ракета+корзина —
39, а не ≥40).

## Этап 4. Экономика (`test_economy`, 6 тестов, 46 проверок)

* Списание монет: больше баланса — отказ без изменений; отрицательное — отказ;
  баланс не уходит в минус.
* Заряды помощников: стартовые 2/2/1/1, списание ровно по 1, пустой помощник
  не списывается, предел 99.
* Бесплатная тестовая покупка: +3 заряда; 2-е и 3-е касание во время
  обработки игнорируются (ровно одно начисление); покупка сохраняется на диск
  и записывается в журнал.
* Предел 99: набор «Пчёлка» при 98 даёт 99; дальше кнопка «Максимум»; набор
  помощников продолжает работать для остальных.
* Улучшения фермы: без монет — отказ, с монетами — списание и новый уровень,
  закрытый участок и наградной декор не покупаются, максимум уровня соблюдается,
  состояние сохраняется.
* Задания: награду нельзя получить до выполнения и нельзя получить дважды.
* В сцене (`test_scenes`): тройное быстрое нажатие на помощника тратит один
  заряд; помощник не тратит ход; Жужа даёт +3 хода; выбор клетки для
  Белки можно отменить без потери заряда.

## Этап 5. Все 10 уровней (`test_levels` + `tests/sim_levels.gd`)

* Каждый уровень пройден ботом без помощников; три звезды достижимы на всех
  уровнях. Симуляция 40 партий на уровень: побед 95–100% (таблица в
  [GAME_DESIGN.md](GAME_DESIGN.md)).
* Лимиты ходов и цели совпадают с ТЗ.
* Награды: уровень 1 — 100 монет + 5 за каждый оставшийся ход; заряды за
  первые прохождения уровней 3/5/7/9; награда за 3★ выдаётся один раз;
  повтор — 25%; поражение ничего не даёт.
* Открытие следующего уровня, сохранение звёзд (лучший результат не
  ухудшается), уровень 10 открывает праздничное пугало, уровни 6/8 — новые
  участки фермы.
* Полное прохождение уровня 1 через настоящую сцену головоломки (ввод →
  анимации → экран результата) — уровень записан как пройденный.

Найдено и исправлено в ходе этапа: числа из JSON приходили как float, и цели
«собрать» не засчитывались — значения приводятся к int; бот «подглядывал»
будущие падения (копия генератора) — теперь моделирует с другим зерном;
уровни на 5 цветах оказались слишком лёгкими — баланс пересчитан.

## Этап 6. Сохранения (`test_save` 6 тестов / 24 проверки, `tools/restart_check.gd`)

* Сохранение → загрузка: монеты, звёзды, ферма, настройки, версия.
* Временный файл после атомарной записи не остаётся.
* Испорченный основной файл → восстановление из резервной копии и починка
  основного; подделанный файл (неверная контрольная сумма) отклоняется;
  испорчены оба → новый профиль.
* Сохранение версии 0 мигрирует в версию 1, недостающие разделы дополняются.
* Повторная победа после «перезапуска» не дублирует награды.
* **Принудительное закрытие:** процесс 1 проходит уровень, покупает набор,
  улучшает дом и завершает себя `kill` без штатного выхода; процесс 2
  загружает сохранение — всё на месте (`VERIFY source=main coins=180 bee=4 house=1 … OK`).
* Перезапуск телефона не проверялся (нет устройства); данные лежат во
  внутреннем хранилище приложения и не зависят от перезагрузки.

…» расширяла экран (перенос строк); стартовый масштаб фермы обрезал дом.

## Как повторить

```bash
cd SolarFarm
godot --headless --path . --import
godot --headless --path . -s tests/run_tests.gd
godot --headless --path . -s tests/sim_levels.gd -- 40
godot --headless --path . -s tools/restart_check.gd -- write; godot --headless --path . -s tools/restart_check.gd -- verify
xvfb-run godot --path . --rendering-driver opengl3 --resolution 720x1280 -s tools/screenshot_tour.gd -- /tmp/shots
```
