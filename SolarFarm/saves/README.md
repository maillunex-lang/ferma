# Сохранения

Игра хранит прогресс только на устройстве, в каталоге данных приложения
(`user://` в Godot):

| Платформа | Путь |
|---|---|
| Android | `/data/data/ru.solarfarm.game/files/save.json` (доступен только самому приложению) |
| Linux (запуск из редактора) | `~/.local/share/godot/app_userdata/Солнечная ферма/save.json` |
| Windows | `%APPDATA%\Godot\app_userdata\Солнечная ферма\save.json` |

Эта папка в проекте оставлена для документации формата; сама игра сюда не
пишет.

## Файлы

* `save.json` — основное сохранение;
* `save_backup.json` — предыдущее корректное сохранение (резервная копия);
* `save.json.tmp` — временный файл атомарной записи (существует доли секунды).

## Формат

```json
{
  "format": "solar_farm_save",
  "version": 1,
  "checksum": "<sha256 от строки payload>",
  "payload": "{\"version\":1,\"coins\":150,...}"
}
```

`payload` — JSON-строка с данными:

| Поле | Содержимое |
|---|---|
| `coins` | баланс монет |
| `levels` | `{"1": {"completed", "stars", "best_moves_left", "three_star_claimed"}, ...}` |
| `helpers` | заряды помощников `rooster`, `squirrel`, `hedgehog`, `bee` |
| `farm` | уровни улучшения объектов фермы |
| `settings` | `music`, `sfx` (0..1), `effects` (`high`/`low`), `fps` (60/30), `hints` |
| `achievements` | `progress` (счётчики событий) и `claimed` (полученные награды заданий) |
| `tutorial` | показанные обучающие подсказки уровней |
| `stats` | сыграно / выиграно, количество тестовых покупок |
| `purchase_log` | последние 50 бесплатных тестовых покупок |

## Надёжность

* Запись атомарная: данные пишутся во временный файл и затем переименовываются,
  поэтому принудительное закрытие не оставляет «половину» файла.
* Сохранение выполняется сразу после каждого значимого события: завершение
  уровня, покупка/начисление зарядов, улучшение фермы, изменение настроек,
  а также при сворачивании приложения.
* При загрузке проверяется контрольная сумма. Если основной файл повреждён или
  изменён вручную — используется резервная копия (игрок увидит уведомление),
  если повреждены оба — создаётся новый профиль.
* Поле `version` позволяет мигрировать старые сохранения в будущих версиях
  (`SaveManager._migrate`), недостающие поля дополняются значениями по
  умолчанию.
